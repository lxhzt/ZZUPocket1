# 应用凭据隔离与资金风险控制

日期：2026-10-26。

## 目标与功能边界

目标是保留正常的本科/研究生课表、教室查询和本地工具，同时防止本 App 成为窃取学校凭据或操作校园卡资金的入口。电费、校园卡和其他资金接口继续停用，原业务代码保留。

本次不采用强制离线或取消统一登录的方案。原协议中的本科教务仍直接使用 CAS 令牌；没有臆造学校不存在的只读授权或改动学校认证协议。

## 本轮整改

1. **按服务与接口限制原生请求**：CAS、EAS、GMS 和停用的资金客户端各有显式能力范围。登录客户端只允许既有登录/MFA 路径；教务客户端只允许现有身份判定、学期、课表、节次、校区、教室类型、楼层、楼栋和教室查询；研究生原生客户端解码路由后只允许三个既有课表模块及会话首页。限制方法、参数名、重复参数和凭据请求头，关闭原生重定向。拒绝发生在 DNS/网络传输之前。
2. **资金客户端底层封锁**：即使绕过上层按钮、Worker 和 EcardClient 方法检查，生产资金客户端仍拒绝所有请求。该边界防止本客户端意外恢复资金能力，不改变学校令牌的服务端权限。
3. **通用诊断通道停止转发令牌**：EAS 的任意地址/路径原始调用入口本身加入诊断关闭检查，不能只依赖调用页面隐藏。
4. **减少闲置凭据**：登录后不保存没有任何使用方的 CAS 刷新令牌。令牌存储初始化时移除历史闲置刷新令牌及停用的一卡通令牌缓存，不删除课表、消费历史、电量记录、房间资料或其他业务数据。现有 CAS 登录令牌和研究生教务会话仍按原用途加密保存。
5. **隔离浏览器通用登录会话**：研究生 WebView 的 CAS `service` 参数只允许现有 GMS 入口（含原协议的 `/stu/cas`）。先同步截取需要采用的 GMS Cookie，再关闭窗口、销毁网页并清除 WebView Cookie 与 WebStorage；网页缓存设置为 `LOAD_NO_CACHE`，不承诺历史磁盘文件的安全擦除。原生 GMS CookieJar 独立保留所需教务会话。
6. **缩短密码留存**：进入短信阶段清空界面密码副本；待验证账密采用五分钟的单调时钟期限，重发短信不延期；超时、退出页面、登录结束或初始登录失败清除待验证引用。取消的请求不再更新已离开的登录界面。JVM String 清除引用不等同于内存安全擦除。
7. **保护输入界面**：隐藏其他应用的覆盖窗口，拒绝被完全或部分遮挡的触摸；密码输入使用密码键盘并关闭自动纠错。移除原界面建议用户设置可信设备以减少短信验证的文案，保留学校要求的验证流程。不会把这些措施称为能够抵御用户授权的恶意输入法、无障碍软件或已失陷操作系统。

以上限制覆盖现有正常调用形态。学校以后改动路径或参数时，请求会被安全拒绝，需要审查后适配，不能自动扩大目的地或权限。

## 验证方式

新增 `CredentialContainmentTest`：使用假凭据、禁止 DNS 的客户端和进程内假传输，验证保留请求、跨服务转发、非法方法和参数、金融工厂封锁、通用诊断入口、CAS service 约束及密码过期。保留此前的金融入口与异常输入测试。

没有登录学校账号，没有真实校园卡或学校业务 API 请求。本地构建使用已有依赖缓存，不访问学校平台。真机上的完整登录、MFA、Cookie 清理和覆盖窗口行为仍需在受控环境验证。

覆盖窗口控制参考 [Android 官方防点击劫持说明](https://developer.android.com/privacy-and-security/risks/tapjacking)。部分遮挡过滤可能影响合法悬浮工具，真机回归需同时检查这类交互与辅助功能，不能将静态配置视为实际设备验证。

本轮最终执行结果见 `security-evidence/credential-containment.json`；发布签名仍需所有者私钥，未签名产物不能直接作为正式分发包。

本轮实际结果：337 项 JVM 测试全部通过（新增 10 项），21 项静态检查全部通过，Lint 为 0 错误、127 警告、6 提示；调试包与发布包均构建成功。正常 EAS 调用测试仅移除了 JVM 环境无法执行的 Android 调试日志拦截器，保留了全部请求策略与传输保护。

最终未签名发布 APK 为 6,161,944 字节，SHA-256：`d66910def727896e5c0757a291d5def49f9d5a27d7d8ff5a7807e4ec7e2e09f1`。已核对编译产物中的包名、备份与明文网络限制、导出组件、系统证书信任，以及直接 `Log.v/d/i/w/e` 引用移除情况；库的其他日志引用仍存在，不能宣称没有任何运行时日志。

## 结论边界

这是一轮应用侧隔离与加固，不是资金绝对安全证明。请求白名单防止本客户端错误转发或调用，并不能阻止攻击者在窃取 CAS 令牌后使用另一份程序。仍需避免原生代码执行、WebView 漏洞、凭据导出和供应链替换等路径。

学校的通用 CAS 权限、免密设置、支付密码重置和付款码授权规则，无法由客户端重新定义。由于本科功能继续使用该通用凭据，目前不能断言“即使应用进程完全失陷也绝不影响资金”。要达到该更强目标，需要学校提供不能访问或换取金融权限的专用授权，或不让应用接触通用学校凭据。

在真机回归、最终签名产物与动态边界验证完成前，PR 应保持草稿，不宣称已完成中等强度安全验收。
