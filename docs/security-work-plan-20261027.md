# 无账号条件下的安全核查计划

日期：2026-10-27。目标：保留正常教务功能，降低从本应用间接危及校园卡资金及个人信息的风险。

## 访问约束

学校侧仅顺序、限量读取已确认公开入口及其直接引用的静态资源；每次请求限制超时与响应大小，不带账号、Cookie 或令牌，不执行下载脚本，不自动跟随跳转。记录证据中的请求与跳转位置后，再判断是否需要读取正常公开页面。禁止端口扫描、接口/目录枚举、账号登录、验证码、密码重置、支付请求及对学校的压力测试。

## 执行顺序与交付

1. 核对当前分支、既有整改及测试证据；保留既有业务数据与资金功能原代码。
2. 追踪本科教务与 CAS 的公开登录入口和静态代码，核查是否存在独立网页会话、服务票据或受限授权。区分官方静态证据、社区实现和未验证后端行为。
3. 对已确认入口观察 TLS、HTTPS 跳转、响应头及静态凭据处理，记录公开访问证据；不以响应头缺失直接推断账号或资金可被攻击。
4. 并行独立复核本应用的凭据、存储、请求、WebView 和组件边界；只对可复现、可明确修复的问题实施整改。
5. 增补本地对抗测试：虚构凭据、进程内传输，覆盖畸形输入、目标绕过、并发与资源限制。统一运行相关单元测试、静态检查；生产代码变更时重新构建和检查发布产物。
6. 输出权限关系、功能取舍、测试覆盖与剩余未知项。把证据及改动更新到既有草稿 PR，未经授权不合并或发布。

## 完成标准

- 每个结论都有当前源代码、公开来源或实际本地执行结果支持。
- 明确本科教务独立授权是否已找到、是否已可安全接入；不能用“未找到”证明“不存在”。
- 当前财务入口保持关闭，教务查询允许范围得到回归验证。
- 发现的明确问题已整改并通过相应验证；所有外部请求均在上述约束内。
- 报告明确区分本地验证与真实设备/学校后端尚未验证的行为，不宣称全局安全或绝对资金隔离。

## 审查后追加的明确整改

发现研究生导入课表共享固定学期标识，退出或换会话后的旧缓存/旧异步结果可能显示在新会话。实施前按以下方式约束改动：

- 复用现有按学期分开的存储键，为每次新网页登录分配持久、不可复用的本地负数学期标识；不把该标识冒充学校身份。
- 同一持久会话恢复继续原分区；旧的无归属记录留存但不自动分给新登录，不删除业务历史。
- 课表行/课程主键、同步状态、周次设置、详情、今日页与桌面组件统一使用当前分区和一次捕获的会话快照。
- 换会话立即撤下旧的学校课表展示，迟到任务不能覆盖新会话。验证分配不回绕、跨分区主键/查询隔离和并发结果失效。
- 不把本次课表隔离扩大宣称为所有本地个人数据的账号访问控制；用户手动专注记录等原有设备本地历史保留，其归属不能靠猜测迁移。
- 追加生产改动后重新统一构建与验证，不把中途构建的结果当作最终源码验证。
