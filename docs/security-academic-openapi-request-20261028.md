# 教务应用最小权限接入需求

日期：2026-10-28。供学校开放平台技术审核使用的需求草案；未提交，不表示学校已承诺提供以下能力。

## 用途与数据范围

应用仅需展示用户本人课表，并提供不含人员身份信息的教室位置、占用及空闲查询。研究生模块在确有使用需求时独立申请。不同模块分开授权；不默认申请目录中所有教务 scope。

| 功能 | 已发现的官方 scope 候选 | 请求边界 |
|---|---|---|
| 本科本人课表 | `dataMarket:v1:view_lima` | 仅当前经验证用户的当前或主动选择学期；课程、时间、周次、地点及必要关联键 |
| 本科教室查询 | `dataMarket:v1:tgxjxbzksjssyxx`、`dataMarket:v1:tgxjxbzksjsjbxx` | 教室位置与占用，不返回授课名单、学生身份或无必要个人信息 |
| 本科必要补充 | `dataMarket:v1:tgxjxbzkspkxx_alpha`、`dataMarket:v1:view_papa` | 仅在上述数据无法满足所需字段时另行说明用途并申请 |
| 研究生本人课表 | `dataMarket:v1:view_echo_papa` | 仅当前经验证用户和所选学期；必要时才申请 `dataMarket:v1:view_delta_yankee` |
| 研究生教室基础信息 | `dataMarket:v1:view_delta_whisky` | 仅必要教室字段；是否支持占用查询需另外确认 |

不申请 `idToken:v1:createIdToken`、财务缴费 scope `date:v3:TCJF`，不申请一卡通、余额、支付、充值、退款、密码重置、用户安全管理或无必要的角色/人员查询。

## 请校方明确的授权契约

1. 确认这些 scope 当前可申请、实际绑定哪些完整接口，以及是否可能通过其返回值或兑换能力取得资金相关权限；后续新增接口是否需要重新审批。
2. 确认客户端凭据和访问令牌仅授权所批准的教务功能；未授予资金、通用身份签发、凭据兑换和无必要用户信息权限。说明有效期、轮换、撤销、审计和异常处理机制。
3. 优先提供按已验证用户身份约束的数据范围。当前公开 `/full` 规范没有说明本人行限制，不能据此承诺私有课表查询。若必须使用经审批的数据集，须明确学校许可的数据范围、部署要求、字段限制及后端职责。
4. 提供不向本 App 暴露统一密码、通用 CAS JWT 或全局 SSO Cookie 的身份确认方式。确认身份回调绑定该应用、不可重放，且不会给应用长期提供可跨服务取得资金权限的用户凭据。
5. 确认请求学号必须绑定可信登录身份，不能由客户端任意指定；用户之间、应用之间及权限组之间均有服务端隔离。
6. 明确所需最小字段、字段类型、学年学期和周次/节次编码、数据刷新时间、校历来源、课表和教室覆盖范围、查询限额以及数据删除要求。

## 应用侧实施承诺与验收要求

- 应用 ClientSecret 和平台访问令牌仅保存在学校批准的后端，不写入 APK、前端资源、日志、备份或客户端返回值；不把应用级密钥作为每名学生的登录凭据。
- App 只取得本应用自己的短期会话和必要业务数据；后端逐请求核验身份、数据主体及权限。不能把全校课表下发后在手机上筛选。
- 接入前核对批准 scope 的全部操作及字段；保持资金出口关闭，不为了接入新服务放开通用网络转发。
- 在校方允许的测试环境或受控非资金条件下，验证本人可读、他人不可读、越 scope 不可读、过期/撤销失效。跨资金边界优先由校方提供拒绝测试或网关权限契约，不进行真实付款、验证码触发或未授权兑换。
- 授权与字段未落实前，不编造 scope、不复用现有移动校园 appId 的通用凭据，也不宣称已完成资金隔离或全部功能迁移。

公开申请流程还涉及单位审批、校内数据中心和学校二级域名；具体申请主体及部署条件应先由学校确认。本草案不包含真实人员资料、账号、密钥或虚构批准信息。
