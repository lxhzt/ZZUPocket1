## 安装包门槛

发布前由 `tools/sign-launch-apk.py` 检查：独立持久签名密钥、v2/v3 签名校验、ZIP 对齐、正式包名/版本/最低 Android 版本、不可调试、禁止备份、禁止明文流量、正式包无实验组件，以及当前应用名称和状态文字确实在包内。实际字节数、文件 SHA-256 和证书 SHA-256 以 [机器可读证据](security-evidence/launch-20261028.json) 为准。

签名使用本地专用密钥，不使用 Android debug 密钥，也不上传私钥或密码。所有者应私下备份整个 `.security-tools/launch-signing/` 目录。重新生成密钥会破坏现有安装的覆盖升级能力。仓库仅保存已经签名的 APK、公开证书指纹和校验摘要。

本地原始构建日志保存在 `.security-tools/launch-20261028-build.log` 与 `.security-tools/launch-20261028-final-build.log`，不随仓库发布。发布工作流只校验并上传已签名的文件，不取得签名密钥、不重新签名，也不执行学校操作。

## 尚未证明的边界

- Android 仪器化运行检查仍为 **0 项实际执行**。JVM 窗口转储样例通过，不代表真实设备的窗口、WebView、Keystore 或遮挡触摸已运行验收。
- 没有使用学校账号、Cookie 或令牌；没有实施学校登录态测试、资金令牌交换、资金操作或对学校的压力测试。
- 学校统一凭据的服务端权限、跨系统资金隔离以及受限教务 Scope 的实际授予和按学生限制数据行的约束仍未验证。
- 真实账号登录兼容性、不同手机厂商系统行为与正式推广条件，仍需要后续独立验证。当前适合预发布安装验证，不能据此宣布面向全校正式推广。

金融调用的本地阻断减少了应用主动触达这些接口的路径，但不会缩小学校服务器赋予统一凭据的权限。该边界与上一阶段结论一致。
