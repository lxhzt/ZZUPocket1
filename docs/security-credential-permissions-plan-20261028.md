# 学校凭据类型与权限核查计划

日期：2026-10-28。范围：核查本应用使用的学校凭据及其跨服务兑换关系；不以手机或学生账号为前提。

1. 对照当前代码列出密码、CAS idToken/userToken、refreshToken、MFA state/gid、CAS 服务票据、全局 Cookie、教务 Cookie、一卡通 tid/accessToken/refreshToken；记录签发方、接收方、持久化与兑换关系。
2. 先读取五个已知公开资源：CAS 公钥、带本科教务 service 的登录页、本科 H5 壳页面、研究生入口、一卡通 H5 壳页面。仅在查看页面引用后，另行选择最多三个必要的静态 JS；不自动爬取。
3. 程序只用 GET、HTTPS/443 和正常证书验证；串行访问，间隔至少一秒；不自动跟随跳转，不保存或回传 Cookie，不发送账号、密码、Authorization 或测试令牌。每轮最多八次请求、单响应三 MiB、总响应八 MiB；失败停止，不重试。
4. 不调用登录、MFA、验证码、令牌兑换、用户资料、付款码、重置密码、支付、充值、退款等业务接口；不扫描端口、目录或 API，不猜测管理/调试入口。
5. 原始页面仅保存在忽略目录；提交的证据仅包含 URL、时间、状态、长度、哈希、脱敏 Cookie 属性及必要静态引用。将代码事实、公开页面事实、历史记录与尚未验证的服务端权限明确区分。
6. 输出凭据权限表和风险判断，纠正“鉴权头不同就相互隔离”“service 参数就是受限 scope”“删除资金代码即可消除凭据跨服务权限”等误解。不把未登录响应或静态代码当作已登录授权边界的证明。

通过条件是证据足以证明应用持有的凭据只满足必要教务用途，并且不能访问或换取资金权限。若无账号条件下不能证明，结论保留为未证实，不能通过伪造凭据或真实资金请求补齐证据。
