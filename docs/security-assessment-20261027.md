# 无账号条件下的应用安全复核

开始日期：2026-10-27。最终复核日期：2026-10-28。状态：无账号条件下的本轮整改与本地验证完成；完整安全验收未完成。

## 核心判断

本轮查到了当前教务网页登录及 Cookie 课表通路，纠正了此前没有充分调查替代授权方式的问题。该通路尚未通过账号验证，不能直接宣称为教务只读授权。详情及固定来源见 [认证核查](security-auth-scope-investigation.md)。

应用的资金网络仍默认关闭，保留原业务代码。客户端隔离减少本应用误用或转发凭据的机会，但不会缩小学校通用 CAS 令牌的服务器权限。本科在线查询仍使用这种令牌，因此“应用进程被攻破也绝不影响资金”尚未获得证明。

## 复核范围与威胁模型

按 [OWASP MASVS](https://mas.owasp.org/MASVS/) 的存储、密码学、认证、网络、平台交互、代码与隐私领域组织复核；未完成其全部要求，不作认证声明。这里的本地并发与畸形输入实验有明确规模，不把“中等强度”当作已有统一验收标准。

| 攻击面 | 当前处理与检查依据 | 尚未覆盖的边界 |
|---|---|---|
| 资金业务 | 功能、调用入口和生产传输客户端分别阻断；后台资金采样关闭 | 被窃取的广泛学校凭据可被拿到应用外使用，其后端权限不由本应用定义 |
| 登录与凭据 | 不保存密码和未用的 CAS refresh token；加密偏好保存必要凭据；密码等待短信有期限 | 本科 JWT 仍长期可用；进程失陷、恶意输入法/获准辅助服务和系统失陷未获得防护证明 |
| HTTPS 与请求转发 | 系统 CA、HTTPS/443、精确域名与接口能力范围、禁止原生自动跳转 | 未做真实设备代理/TLS 对抗实验；没有校验证书钉扎或后端权限范围 |
| Cookie 与退出 | 只持久化记录协议需要的研究生应用 Cookie；响应限长；旧请求与会话代际绑定 | Cookie 值的服务器权限仍未知；删除本地副本不等于服务器撤销已盗副本 |
| WebView 与界面 | 域限制、SSL 错误取消、本地资源/混合内容/调试关闭；登录结束清浏览器会话；独立 Dialog 覆盖层与截图保护 | Android 页面跳转、清理时序、输入与覆盖层行为尚无设备实验；宿主 App 仍控制 WebView |
| 组件与外部输入 | 导出入口限制、桌面路由白名单、不可变待处理 Intent；发布 APK 组件检查 | 未做设备上的恶意应用 IPC 实验 |
| 资源耗尽与解析 | 解压后响应上界、JSON 嵌套/文本解析上界、图片尺寸和字节限制；本地并发与畸形数据实验 | 无真实设备内存/帧率/长时运行数据；不能推断学校服务承载能力 |
| 本地数据与跨会话展示 | 研究生导入课表改为本地会话分区；旧记录保留；当前视图和小组件绑定当前分区 | 应用私有数据库没有全库加密，手动日程/专注等设备本地历史不是学校账号访问控制系统；不覆盖系统失陷或已获设备访问权者 |
| 日志与备份 | 不记录响应秘密，发布版移除直接常规 Log 调用；禁备份与迁移 | 不能宣称没有任何库日志或 JVM 字符串被可靠擦除 |
| 构建与依赖 | 官方仓库优先，保留镜像后备；Wrapper 校验；依赖 SHA-256 基线与严格验证；公开漏洞数据库查询 | 首次以当前缓存建立基线不是所有依赖的独立官方来源核验；未知漏洞、构建机/JDK/SDK 可信性仍需单独考虑 |

## 本轮明确整改

1. 诊断页采用研究生会话前先捕获 Cookie，再关闭清理登录窗口，修复关闭与读取的竞态。
2. 研究生登录与持久会话恢复只保留 `cn_com_southsoft_gmis_stu`。原仓库协议记录证明三项查询只需该值；过滤 CAS `SESSION`/`TGC` 与其他 Cookie，旧认证字段原地收紧，不删除业务数据。
3. 原生 GMS 请求和 Cookie 响应绑定登录代际，退出/重登后拒绝迟到的旧响应、Cookie 和会话标识。响应 Cookie 增加名称 128、路径 2048、值 4096 字符上限。
4. 为研究生登录的独立 Dialog Window 补上覆盖层隐藏与截图保护，WebView 拒绝全部或部分遮挡的触摸；纠正“密码完全不经过应用”的文案。
5. 为研究生导入课表增加本地会话分区，避免共享固定学期标识造成跨会话复用；课表、课程详情、同步记录、周次设置、今日页和桌面组件统一使用分区快照。每次新网页登录分配新的负数标识，Cookie、分区、计数器与时间单次提交；恢复同一持久会话沿用分区，退出保留计数器，避免编号重用。Session/Course 主键包含分区，旧任务即使在撤销后完成数据库写入，也只会写入不可由新会话读取的旧分区。共享的旧 `-10001` 记录保留，不自动分给任何新登录。本科响应里的负数学期标识被过滤，防止占用该命名空间。
6. 调整构建仓库优先顺序并增加依赖字节校验，默认本地验证脚本采用 strict 模式。没有擅自升级业务依赖。
7. 修复本地数据库/偏好读取异常可能终止长期监听的问题。普通读取错误保留空的学校课表展示并继续监听；取消正常传播，旧会话迟到的错误不能清空新会话。补充错误后重试、后续登录与退出的实际协程测试。

会话分区复用现有表按学期过滤的结构，无需修改数据库 schema 或删除历史。升级前的研究生缓存归属未知，重新同步后才显示当前导入课表；新网页登录也会重新同步并重新确定该分区的教学周设置。原有手动专注记录、标签和其他设备本地历史没有被猜测归属或删除，它们不属于本次学校导入课表的访问隔离承诺。
